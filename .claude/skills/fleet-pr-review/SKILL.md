# Fleet 적대 PR 리뷰 (로컬)

변경·스펙을 여러 렌즈로 적대 검증한다. **Codex 봇과 역할이 겹치므로 클라우드 Action으로 만들지 않는다** —
용도는 Codex 한도 소진 시 대체 / PR 전 자가리뷰.

## 언제

"PR/스펙 적대 리뷰", "독립 검증", Codex 미가용 시 리뷰 대체.

## 행동 (CLI 비종속)

1. **규모·렌즈 판정** — 용도별 계층(권위: AGENTS.md 「Codex 리뷰 운영 기준」 자가리뷰 계층화 절):
   - **PR 전 자가리뷰(봇 리뷰 예정 = 기본)** → **봇 공백 렌즈만**: 프레임 전복(스펙/갭 전제 자체
     재검)·성능 정량·테스트 커버리지·동적 검증. Codex 강점(계약 drift·보안 퍼징·race)은 봇에 위임.
     **전제: 머지 전 Codex 리뷰 완료(리뷰/👍) 확인** — 미완료·무응답 상태로 머지하려면 아래 대체
     모드(풀 렌즈)를 먼저 돌려야 한다(ADR-0014).
   - **Codex 미가용 대체** → 풀 렌즈(아래 2의 P1 신호 + 보안·정합성·범위).
   - **규모 연동** — diff 소형(P1 신호 비접점)이면 find 렌즈 3~4로 충분. P1 신호(계약·보안·게이트)
     접점이면 해당 렌즈만 추가. 렌즈를 넓히기 전에 렌즈당 기대 수확을 따진다.
2. **렌즈 분할** — Fleet 특화 P1 신호(AGENTS.md 「Codex 리뷰 운영 기준」: 코어 Electron 유입·
   ApprovalGate 우회·IPC/FleetBridge drift·provider 계약·FLEET_E2E 가드·engine/lockfile·release 안전장치)
   + 보안·정합성·범위 렌즈. 1의 판정으로 선별한 부분집합만 가동.
3. **find** — 렌즈별 **독립 서브에이전트 디스패치**로 결함 탐지(구조화 출력: severity·위치·문제·제안).
   Claude Code 로컬 = `fleet-finder` 에이전트(`.claude/agents/`). 기계적 렌즈(주석/핀/나열 스윕)는
   하위 effort/모델로 디스패치한다.
   - **필수 — 자기 주장을 반증 대상으로 명시한다.** PR 본문·커밋 본문의 사실 주장을 목록으로 뽑아
     프롬프트에 넣고 「이것들을 특히 반증하라」고 지정한다. 이 한 문단이 있고 없고가 수확을 가른다 —
     #319·#321 둘 다 이 지정으로 **작성자(나)의 주장 쪽이 깨졌다**. 빠뜨리면 렌즈가 표류한다.
   - 렌즈 프롬프트는 즉석에서 짓지 말고 아래 **렌즈 템플릿**에서 가져다 쓴다.
4. **verify(refute)** — 각 발견을 별도 서브에이전트가 refute 시도(불확실하면 거짓양성으로 기각).
   Claude Code 로컬 = `fleet-refuter` 에이전트 — find≠verify 가 에이전트 타입 수준에서 분리된다.
   **이 단계는 규모 판정과 무관하게 축소 금지**(세션 티어 유지).
5. **합성** — 확정 발견만 severity별로. 거짓양성은 사유와 함께 기록.

## 렌즈 템플릿 (대체 모드 기본 4종)

렌즈의 질이 그날 프롬프트를 쓴 사람의 통찰에 좌우되면 리뷰가 재현되지 않는다. 아래 넷을 기본으로
가동하고, P1 신호 접점이면 해당 렌즈만 추가한다. 각 「주입」은 **생략하면 그 렌즈가 무력해지는** 문장이다.

| 렌즈 | 무엇을 묻는가 | 프롬프트에 반드시 주입 |
| --- | --- | --- |
| **주장 정합성** | 본문의 사실 주장이 1차 증거와 맞는가 | 「**역사적 주장**(선례·건수·날짜·버전)은 기억이나 요약이 아니라 **원문을 열고** 확인하라 — 과거 PR·이슈는 `mcp__github__*`, 의존 관계는 락파일을 직접 읽어라.」 + 직전에 틀린 주장 유형이 있으면 그것을 명시 |
| **오탐 축** | 이 변경이 **잘못된 신호**를 내는 지점 | 「이 게이트·센서가 red/경고가 되는 경로를 **취약점 외의 것까지 전부** 열거하라(네트워크·레지스트리 오류·환경 차이·시각 의존). 오탐이 상시화되면 방치→제거로 끝나므로 오탐 축이 P1 이다.」 |
| **테스트 검출력** | 이 테스트가 **못 막는** 회귀 | 「**구성 가능한 반례**를 제시하고, 그 입력에서 각 단언이 통과/실패하는지 명시하라. 「테스트가 있다」가 아니라 「이 우회는 통과한다」를 찾아라.」 |
| **외부 의미론** | 런타임·API·CLI 의 **실제** 동작 | 「라이브러리·API·SDK·CLI·모델 관련은 **context7 MCP 로 현행 문서를 받아 교차검증**하라(AGENTS.md 「리뷰 피드백 교차검증」 — 선택이 아니라 요구다). 원문 문서·소스는 그 위에 얹는 보강 증거이지 대체재가 아니다. context7 이 미가용이면 그 사실과 대체 근거를 명시하고, 확인 못 한 것은 「미확인」으로 표시해 단정하지 말 것.」 |

실측 근거: #321 에서 최대 수확(선례 오인 2건·건수 인플레이션)은 **주장 정합성** 렌즈가 냈고, 그 렌즈가
작동한 이유는 「직전 PR 에서 선례 인용을 틀렸으니 특히 의심하라」를 프롬프트에 넣었기 때문이다.
같은 PR 의 **오탐 축** 렌즈는 fail-hard 설계를 무너뜨린 근거(레지스트리 5xx = 취약점과 구분 불가)를 냈다.

## 뮤테이션 규율 (핀 테스트를 낸 PR 에서)

「뮤테이션으로 검증했다」가 검증의 착시가 되는 실패가 실제로 났다(#321). 두 규칙으로 막는다.

1. **오라클을 뮤턴트보다 먼저 검증한다.** 「뮤턴트가 적용됐는가」의 판정 수단을 먼저 시험하라 —
   #321 은 신규 파일이라 `git diff` 가 항상 비어 **미적용 뮤턴트가 「검출됨」으로 보였다**(`cmp` 로 교정).
2. **우회 클래스를 먼저 열거하고 클래스당 뮤턴트를 만든다.** 최소 네 층 — 문법 층(텍스트 치환) ·
   의미 층(`|| true`·`exit 0` 등 상태 삼킴) · 스코프 층(`if:` 조건부 skip) · **상위 컨테이너 층**
   (잡 레벨 키·파서가 블록을 잘못 자르는 형태). #321 의 최초 뮤턴트 9종은 전부 문법 층뿐이라
   10/10 GREEN 을 유지한 채 잡을 무력화하는 우회 5종을 하나도 짚지 못했다.

## 주의

- find와 verify는 **다른 에이전트**로(자기검증 편향 방지).
- 리뷰 지적의 라이브러리/모델 관련은 context7로 교차검증 후 수용/반박.
- 렌즈 축소는 find 폭에만 적용 — refute 규율·P1 신호 접점 렌즈는 지키는 게 계층화의 전제다.
- **기각된 후보는 사유와 함께 PR 코멘트에 남긴다.** refuter 의 기본 자세가 「기각」이라 과잉 기각의
  위험이 있는데, 그걸 알 유일한 방법이 기록이다 — 나중에 사고가 나면 과거 기각 목록을 먼저 grep 한다.
