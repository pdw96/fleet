## 맥락

Phase B(#197)로 문 ② fleet-server 를 컨테이너로 헤드리스 구동하면, 서버는 `FLEET_SECRET_KEY`·
`FLEET_ACCESS_*`(터널/Access·암호화 시크릿)를 env 로 받는다. 이 서버가 spawn 하는 자식(CLI 세션·
detect/probe·MCP stdio·verify·git)은 실측상 `env` 옵션 부재로 `process.env` 를 전량 상속했다 —
즉 워크스페이스·MCP 코드가 서버 시크릿을 볼 수 있었다. 또 B5 는 handshake 시점 인증만 했고(#209 이관),
소켓 수명 중 JWT 만료 후에도 연결이 유지됐다. 두 경계를 어디까지 어떻게 닫을지 결정이 필요했다.

## 결정

1. **자식 env = allowlist(denylist 아님) 2단**: 런타임 base(전 자식 공통 최소·`FLEET_*`/`NODE_OPTIONS` 배제)
   + CLI 세션 전용 provider 키. 엔진이 spawn 하는 **전 자식**(형제 verify/git 포함)에 적용해 **서버 env
   시크릿(FLEET_\*)을 자식에서 제거**한다. 미주입=현행 상속(데스크톱 무회귀).
2. **소켓 exp-시한 종료**: handshake 시 검증한 JWT 의 `exp` 를 소켓에 기록 → 만료 시각에 서버가 소켓을 닫는다
   (주기 JWKS 재검증 대신). verifier 는 `exp` 부재/비유한수를 fail-closed(401)로 처리한다.
3. **보장 범위 명시**: B6 은 "서버 env 시크릿 격리"까지다. 워크스페이스 명령(verify/git)이 같은 uid·공유
   `cli-auth` 볼륨으로 **자격파일**을 읽는 것은 env 로 안 닫히며 **완전 격리는 Phase C**(별도 uid/RO 마운트/
   per-run worktree)로 둔다.

## 고려한 대안 / 기각 사유

- **denylist(차단 목록)**: 신종 시크릿(`FLEET_NEW_*`·임의 토큰)이 기본 통과 → 유출 표면이 미래에 조용히
  넓어진다. allowlist 는 "명시 추가만 통과"라 신종 시크릿을 기본 차단 → 채택.
- **3번째 env 카테고리(verify/git 에 isolated temp HOME)**: cli-auth 파일 접근을 막으려는 시도. 그러나
  자식이 같은 uid(node)로 실행돼 `os.homedir()` 가 `$HOME` 없이도 `getpwuid`→`/home/node` 로 폴백 →
  **절대경로 직접 read 가 여전히 가능**(temp HOME 은 `~` 편의 접근만 차단). 또 HOME 제거는 git(`~/.gitconfig`)·
  npm(`~/.npmrc`·캐시)을 깨뜨린다. **불완전+파손 위험으로 기각** — 근본 해결은 파일시스템 격리(Phase C).
- **주기 JWKS 재검증(소켓 수명 중)**: 만료 전 재조회는 판정을 바꾸지 못한다(Access 는 철회를 토큰 만료로
  표현·키 롤오버는 다음 handshake 가 흡수). exp-시한 종료가 더 단순·등가 → 채택. 관리자 revoke 가 만료 전
  소켓에 즉시 반영되지 않는 잔여는 수용(다음 handshake 차단).
- **cli-auth RO 분리(문 ② 만 읽기전용)**: #195 실측상 동시 사용 간섭 미관측이라 선제 분리는 과함. RW 공유
  유지하되 refresh 로테이션 경합을 잔여 리스크로 문서화(신호 시 후속).

## 결과 (Consequences)

- **좋은 점**: 서버 시크릿이 워크스페이스/MCP 코드에 안 샌다(형제 verify/git 포함 완결). 소켓이 토큰 수명을
  넘겨 살아있지 않다. 데스크톱은 미주입이라 무회귀.
- **감수하는 비용**: (a) cli-auth 파일 exfil 은 단일 사용자 Phase B 위협모델(워크스페이스=cli-auth 동일 주체)
  하에서 수용하고 완전 격리를 Phase C 로 미룬다. (b) 관리자 조기 revoke 는 다음 handshake 에서만 차단. (c)
  allowlist 는 CLI 실 env 요구에 맞춰 경험적 튜닝이 필요(enterprise/proxy 변수는 named 추가만 — 와일드카드 금지).
- **재검토 트리거**: 다중 사용자/다중 인스턴스 도입, cli-auth refresh 경합 관측, per-run worktree(Phase C) 착수.
