## 맥락

ADR-0017 이 **1.0 의 제품 표면을 Windows / Linux 데스크톱 전용**으로 확정하고 셀프호스트 서버를
post-1.0 으로 미뤘다(2026-08-24). 그런데 **백로그 라벨이 그 귀결을 반영하지 않았다.**

열린 이슈 36건 중 `tier:next` 는 20건이고, 그중 **3건이 ADR-0017 이 post-1.0 으로 미룬 표면을
향한다**:

| 이슈 | 제목 | 표면 |
|---|---|---|
| #251 | feat(ade-1): Workbench 코어(**서버 표면**) — 일급 도메인·공유 권위 CAS·인스턴스 배타·통합 WAL | 서버 |
| #253 | feat(ade-1): Workbench 표면 — '작업' 홈 탭·카드 그리드·모바일·**bench 채널 배선** | 서버 백엔드 의존 |
| #254 | feat(ade-1): Workbench 배포·검증 인프라 — **bench 볼륨·nightly(docker) 게이트 신설**·push-parity | 컨테이너 배포 |

#251 은 제목이 스스로 「서버 표면」이라 말하고, #254 는 배포 대상이 곧 컨테이너다. ADR-0017 은
「셀프호스트 서버 편입은 post-1.0」이라고 적었고 `electron-builder.yml:7`(`- '!out/server/**'`)이 그
결정을 배포 아티팩트에서 이미 집행하고 있다. 즉 **이 3건이 완성돼도 1.0 사용자에게는 배달되지
않는다.**

이건 문서 부정합이 아니라 **착수 대상 선택 알고리즘의 입력 오염**이다. `AGENTS.md`
「백로그 착수 절차」 1단계가 *"`tier:next` 최상위를 집는다"* 이고 `fleet-backlog-induction` 스킬이
그 절차를 실행 래퍼로 갖는다. 라벨이 곧 착수 큐이므로, post-1.0 표면이 `tier:next` 에 있는 한
**1.0 트랙과 매 사이클 경쟁한다.**

실측이 그 경쟁의 결과를 보여준다:

- **1.0 트랙**(#294~#306, 13건)은 2026-08-24 생성 이후 9일간 **12건이 `updated_at == created_at`**
  (착수 0). 같은 기간 머지된 2건(#309·#312)은 프로세스·하드닝이다.
- **ADE 트랙**(#251)은 코멘트 124건 · PR 3건(PR3a~3c, 최종 `af7ef12` 2026-08-13)이 투입됐다.
- `v0.1.0`(2026-06-21) 이후 릴리스는 **0건**(73일).

관심이 1.0 으로 옮겨가지 않았고, 라벨은 그 상태를 막기는커녕 정당화하고 있다.

## 결정

**1.0 stable 태그가 나갈 때까지 ADE·서버 표면 트랙을 동결한다.** 구체적으로:

1. **#251 · #253 · #254 를 `tier:next` → `tier:later` 로 격하한다.** 코드·이슈·테스트는 그대로
   둔다(ADR-0017 이 「서버 코드 제거」를 유해로 기각한 것과 같은 근거 — 되돌릴 비용이 크다).
   #250(메타 트래커, `tier` 무라벨) · #252 · #255 · #193 · #310 은 **이미 `tier:later` 이거나 메타라
   변경 없다** — 드리프트는 위 3건뿐이다.
2. **1.0 stable 태그 전까지 ADE·서버 표면 이슈를 `tier:next` 로 승격하지 않는다.** 예외는
   ADR-0017 이 명시한 재검토 트리거가 **실제로 발생**한 경우뿐이며, 그때도 트리거를 근거로 인용해
   연다.
3. **동결 해제 조건 = `v1.0.0` stable 태그 발행.** 그 시점에 이 ADR 은 자동으로 효력을 잃고,
   ADE 트랙은 통상 재랭킹 대상으로 복귀한다.

이 결정은 **새 판단이 아니라 ADR-0017 이 이미 내린 판단을 라벨에 반영하는 것**이다. 절차·게이트·
문서를 하나도 추가하지 않으므로 「프로세스 net-zero」(어드바이저 원칙 6)의 짝짓기 대상이 아니다 —
총량이 늘지 않고 줄어든다.

## 고려한 대안 / 기각 사유

- **`tier:frozen` 라벨 신설**: 「나중」과 「1.0 전까지 금지」를 구분해 기계 판정이 가능해진다는 이점이
  있다. 그러나 라벨 분류체계(`area:*`/`tier:*`/`type:*`)에 축을 하나 더 얹는 유지비가 붙고, 보드
  Auto-add 워크플로가 `tier:` 라벨 매칭으로 도는 탓에 동작 확인·문서 갱신이 따라온다. 동결이
  **한시적**(1.0 까지)이라 영구 분류축을 만들 값을 못 한다. → 기각. `tier:later` + 이 ADR 로 충분하다.
- **이슈 close**: 되돌릴 때 컨텍스트(#251 코멘트 124건 · refute 이력)를 잃는다. 동결은 폐기가
  아니다. → 기각.
- **아무것도 하지 않는다(문서로만 「1.0 우선」 선언)**: 지난 9일이 그 방식의 실측 결과다 —
  ADR-0017/0018 이 이미 문서로 1.0 우선을 선언했는데 착수는 1.0 트랙으로 가지 않았다. 착수 큐가
  라벨이므로 라벨을 고치지 않으면 선언은 집행되지 않는다. → 기각.
- **ADE 트랙을 1.0 범위로 편입한다**: 표면이 두 배가 되면 출시 기준도 두 배다(ADR-0017 이 셀프호스트
  편입을 기각한 것과 동일 논거). 게다가 #254 는 nightly docker 게이트 **신설**이라 1.0 전에 CI 표면을
  넓힌다. → 기각.

## 결과 (Consequences)

- **얻는 것**: `tier:next` 20건이 「1.0 트랙 13 + 하드닝 4」로 정리돼, 착수 절차 1단계가 집는 최상위가
  구조적으로 1.0 항목이 된다. 「무엇을 할지」 판단이 라벨 하나로 좁혀진다(사용자가 지목한 통증 2).
- **감수하는 비용**: ① #251 의 미착지 후속(PR3 이후 잔여 T항목)이 컨텍스트가 식은 채로 대기한다 —
  재개 시 재파악 비용이 든다. ② ADE 트랙에 이미 투입된 노력의 회수가 1.0 이후로 미뤄진다(매몰비용
  회수 욕구가 이 결정의 최대 적이며, 그것이 정확히 이 ADR 이 필요한 이유다).
- **재검토 트리거**: ① `v1.0.0` stable 태그 발행 → 자동 해제. ② 1.0 트랙이 착수됐는데도 8주 내
  RC 가 안 나오면 동결의 효과가 없었다는 뜻이므로 원인을 재진단한다(동결을 연장하지 말고
  이 ADR 을 supersede). ③ ADR-0017 의 재검토 트리거가 발동해 서버가 1.0 표면으로 편입되면 이 ADR 은
  즉시 무효다.
