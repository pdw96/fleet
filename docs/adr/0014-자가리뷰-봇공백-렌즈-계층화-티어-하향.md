## 맥락

자가(로컬) 적대 리뷰가 19~22 에이전트 규모까지 커졌는데 확정 결함은 0~5건(P3 위주)에
그쳤고(B5/B6 실측), PR 에는 이미 Codex+CodeRabbit 2봇 리뷰가 붙어 렌즈가 중복된다.
서브에이전트 fan-out 은 전 단계가 세션 티어를 상속해 기계적 단계(스윕·수집·나열)에도 최고
티어가 든다. 2026-07 현행 공식 문서가 이 방향을 뒷받침한다: Opus 5 세대 프롬프팅 가이드는
과잉 위임·과잉 검증 스캐폴딩 억제를 명시(이전 세대 권고의 반전)하고, Claude Code
prompt-caching 문서는 서브에이전트가 독립 캐시·5분 TTL 이라 동일 전문의 프롬프트 중복
탑재가 배수 과금임을 명시한다.

## 결정

자가리뷰는 **봇 공백 렌즈**(프레임 전복·성능 정량·커버리지·동적 검증 — Codex 리뷰 502건
실측 분류의 공백 축)를 기본으로 계층화하고, 풀 렌즈는 P1 신호(계약·보안) 접점 또는 Codex
미가용 대체에만 가동한다. **축소 적용의 전제 = 머지 전 Codex 리뷰 완료(리뷰 또는 👍 clean)
확인** — Codex 무응답 fallback 으로 머지하려면 P1 신호 렌즈를 포함한 풀 렌즈 자가리뷰가
선행되어야 한다(Codex 는 required check 가 아니므로, ADR-0001). refute(verify) 규율은
축소하지 않는다. 서브에이전트 fan-out 은 기계적 단계를 하위 effort/모델로 디스패치하고
판정 단계(refute·judge·합성)만 세션 티어를 유지한다.

## 고려한 대안 / 기각 사유

- **현상 유지(풀 렌즈 상시)**: 실측상 확정 수확이 렌즈 3~4 구성(C3/C5)과 동등한데 토큰은
  4~5배 → 기각.
- **자가리뷰 전면 폐지(봇 전적 위임)**: Codex 는 required check 가 아니고 무응답 사례가
  실존(C5, ~16분)하며, 봇 공백 축(프레임 전복·동적 검증 등)은 봇이 구조적으로 못 잡는다
  → 기각.
- **전 단계 하위 모델 fan-out**: refute/judge 판정 품질이 오탐 제거 실효의 근원(적대
  self-verify 가 find 과대평가를 반복 정정) → 판정 단계는 세션 티어 유지로 한정.

## 결과 (Consequences)

리뷰 fan-out 변동비가 대폭 준다(find 폭 축소 + 기계 단계 하위 티어). 감수하는 비용: 축소
구성이 놓칠 수 있는 결함은 봇 리뷰 + refute 이중망과 완료 전제(머지 전 Codex 확인)에
의존한다. 재검토 트리거: ① 축소 구성의 확정 수확이 풀 렌즈 대비 저하로 관측되면 렌즈
재확장(다음 PR 사이클 체크포인트), ② Codex 무응답이 상례화되면 축소 전제 재설계.
