## 맥락
ADR-0007 은 `cutoff-gap-audit`·`backlog-rerank` 두 클라우드 워크플로(`anthropics/claude-code-action`)를
"진짜 능력화"하되, 비신뢰 서드파티 문서(context7 MCP) 주입 + 시크릿 보유 + 공개 이슈 게시라는 exfil
삼요소를 credential 격리(2-잡 분리)로 막았다. 그러면서 하단에 **"레포 public 전환 시 폐쇄 필수"**
(에이전트에서 Bash·시크릿 제거)를 명시적 잔여로 남겼다 — 당시 레포는 private 이었기 때문이다.

레포는 그 폐쇄 없이 public 이 됐다(#228 공개 노출 감사가 이 미이행을 적발). 착수 전 사실확인(3렌즈
적대검증)으로 부분완화 안들의 실효를 검증한 결과:

- **A(에이전트 `Bash(gh issue view:*)` 제거) = 보안 극장.** 그 프리픽스 제약 툴은 `env`/`cat` 을
  애초에 못 돌려 시크릿 읽기 벡터였던 적이 없다. 반대로 남는 `Read` 툴은 경로 제약이 없어 리눅스 러너의
  `/proc/self/environ` 을 읽어 시크릿 전량을 얻는다(`Read` 는 그 경로에 allowed 판정 — Bash 는 내장 가드로
  차단되는데). 즉 닫혀 있던 문을 닫고 열린 문은 둔다.
- **B(로컬 프록시로 시크릿을 env 밖에 두기) = 구조적 부분해.** claude-code-action 은 스텝 `process.env`
  전체를 에이전트에 넘기고, GitHub Actions 는 `with:` 입력을 `INPUT_*` 로 주입하므로
  `INPUT_CLAUDE_CODE_OAUTH_TOKEN`(구독 토큰=최고가치 시크릿)이 **제거 불가능하게** 남는다. 프록시는
  confused-deputy(인증된 egress 를 열어줌)라 exfil 을 형태만 바꾼다.
- **시크릿 스캔 강화(리터럴→인코딩 탐지)** 는 인코딩 공간이 무한해 근본적으로 우회 가능하고, 로그·MCP
  쿼리 등 스캔 밖 채널이 남는다 — 통제가 아니라 위생.

한편 실행 이력은 `cutoff-gap-audit` 2회(둘 다 2026-06-24·1회는 실패), `backlog-rerank` **0회**로,
약 1개월간 재실행이 없다. 클라우드가 로컬 대비 주는 순증분은 `workflow_dispatch` 버튼 하나뿐이고
(cron cadence 는 ADR-0007 이 구독 쿼터로 이미 기각), 두 능력은 `.claude/skills/` 스킬로 로컬에서 그대로
돈다. context7 도 로컬은 이미 무인증(키 불요)으로 동작한다.

## 결정
**두 클라우드 워크플로(`cutoff-gap-audit.yml`·`backlog-rerank.yml`)를 폐기하고, `fleet-cutoff-gap-audit`·
`fleet-backlog-rerank` 스킬을 로컬 `Skill` 툴 전용으로 일원화한다.** ADR-0007 이 요구한 "잔여 폐쇄"를
문자 그대로 만족하는 유일한 조치가 "에이전트를 시크릿 없이 실행"인데 `CLAUDE_CODE_OAUTH_TOKEN` 없이는
이 액션이 못 도므로, 논리적으로 **폐기(C)** 로 수렴한다.

부수 정리: 클라우드 계약 강제 서브시스템(`skills-lint.mjs` 의 `parseCloudTools`·`scanCloudContract`·
`extractFlagValue` + 테스트 + 두 SKILL.md 의 `cloud-tools` frontmatter)은 참조 워크플로가 사라져
inert(죽은 코드)가 되므로 함께 제거한다.

## 고려한 대안 / 기각 사유
- **A(Bash·context7 키 제거로 부분완화하고 워크플로 유지)**: `Read`/`proc`·`INPUT_*` OAuth 토큰이 남아
  ADR-0007 이 요구한 폐쇄를 달성하지 못한다(보안 극장) → 기각.
- **B(로컬 프록시로 시크릿 env 격리)**: 최고가치 시크릿(구독 토큰)이 구조적으로 남고, 40~60줄 프록시 +
  SSE 중계 + 수명관리를 연 0~2회 실행에 붙이는 건 ADR-0003 위반 → 기각.
- **클라우드 계약 lint(`scanCloudContract`)만 남겨 미래 tripwire 로 유지**: `cloud-tools` 계약이 사라지면
  조기 반환하는 죽은 코드다. 살아있는 tripwire 로 만들려면 "임의 claude-code-action 사용 시 발화"로
  재설계해야 하는데, 워크플로 0개 레포에 그 유지비용은 ADR-0003 에 걸린다. 재도입 시 그 PR 의 보안
  리뷰에서 가드를 함께 되살린다 → 지금은 기각.

## 결과 (Consequences)
- **능력 손실 0**: 두 감사·재랭킹은 로컬 스킬로 동일하게 수행된다(오히려 이 세션의 #228 감사·사실확인이
  로컬 fan-out 워크플로로 실행됐다). 잃는 것은 웹 dispatch 버튼뿐.
- **공격 표면 제거**: 비신뢰 주입 + 시크릿 + 공개 게시가 한 프로세스에 모이던 exfil 삼요소가 소멸한다.
  `CONTEXT7_API_KEY` GitHub 시크릿도 참조처를 잃어 제거 대상(운영자 수동 정리 — 로테이션 불요).
- **감사 표면 축소**: 워크플로 2종 + skills-lint 계약 서브시스템이 사라져 유지·리뷰 대상이 준다.
- **재검토 트리거**: 클라우드 cadence 실수요가 재발하고(로컬 실행이 병목으로 입증), 구독-OAuth 를 CI 에
  안전히 태우는 공식 경로가 생기면(현재 없음 — memory:codex-ci-gate-auth) 재설계로 재도입한다. 그때는
  claude-code-action 보안 가드(gh-egress·credential 격리)를 그 PR 에서 함께 되살린다.
