## 맥락

`.npmrc` 의 `engine-strict=true` 때문에 `package.json#engines.node` 가 의존성 트리의 실제 바닥과
어긋나면 `npm ci` 가 EBADENGINE 로 하드 실패한다(transitive 까지 강제). AGENTS.md 는 이 드리프트를
**Fleet 특화 P1 신호**로 등재해 두었지만, 정합을 지키는 수단은 **손으로 돌리는 점 표본**이었다.

그 수단이 하루 안에 두 번 무너졌다:

- #280 이 「결정자는 `which@7` 단독」으로 문단을 동기화 → **20분 뒤** #279(jsdom 30)가 무효화 → #281 재정정.
- 손으로 쓴 검증 절차 자체가 4라운드에 걸쳐 P1 5건을 맞았다 — 점 표본을 tightness 증명으로 취급,
  `optional` 미제외, 락파일 미러를 권위로 읽음, `--omit=dev` 카브아웃이 사실과 반대 등.

점 표본이 부족한 것은 노력 부족이 아니라 **구조적**이다. 탐침 목록이 수동이라 구간 내부·상단에서
새로 거부하는 패키지를 못 잡고, 「그 지점에서 차단하는 패키지」는 결정자 **후보**일 뿐 확정이 아니다
(`>=24.14.1` 을 요구하는 패키지는 탐침 24.14.0 에서 차단되지만 실제 하한은 24.15.0 경계를 정하지 않는다).

## 결정

셋을 함께 정한다.

1. **정합을 범위 교집합으로 기계 강제한다.** semver `Range.set` 의 각 conjunction 은 정확히 하나의
   구간으로 접히므로, 락파일의 전 `engines.node` 선언을 disjoint 구간 리스트로 바꿔 순차 교집합하면
   트리가 허용하는 집합이 **정확히** 나온다. 선언과의 차집합을 양방향으로 내어 **과대선언**
   (EBADENGINE 예정)과 **과소선언**(근거 없는 배제)을 각각 구체적인 구간으로 보고한다. 락파일 루트
   `packages[""]` 미러 드리프트도 같은 게이트가 본다. 배선 = `scripts/engines-floor.test.ts`
   (기존 `verify` 체인 안 · 새 CI 잡·새 npm 스크립트 0 — #137·#140 선례).
2. **결정자·차순위 패키지 열거를 AGENTS.md 에서 제거한다.** 의존성 범프마다 바뀌는 값이라 산문에
   두면 반드시 낡는다. 현재 값이 필요하면 `node scripts/engines-floor.mjs` 가 그 자리에서 낸다.
3. **판정은 양방향 하드 실패**로 둔다(과대선언도 과소선언도 RED).

## 고려한 대안 / 기각 사유

- **결정자 열거를 문서에 두되 게이트가 그 열거까지 핀한다** → 기각. 이 방향은 드리프트를 *막는* 게
  아니라 *경보*로 바꾼다 — 결정자가 바뀔 때마다 CI 가 RED 가 되어 문서 편집 PR 을 강제하므로, 하루에
  PR 3건을 만든 바로 그 churn 을 제도화한다. 근본 해법은 **휘발성 사실을 산문에서 빼는 것**이다.
- **점 표본을 자동화(탐침 목록을 스크립트에 하드코딩)** → 기각. 표본의 구조적 한계(구간 내부 미탐지·
  결정자 오분류)를 그대로 물려받으면서 「자동이니 정확하다」는 잘못된 확신만 얻는다.
- **과대선언만 막고 과소선언은 경고** → 기각. 과소선언을 허용하면 선언이 「트리 범위를 그대로 전개한
  것」이라는 AGENTS.md 의 정직성 주장이 조용히 거짓이 된다. 다만 이 선택에는 실제 비용이 있다(아래).
- **`semver` 의존 없이 직접 파서 작성** → 기각. 트리에 실재하는 범위만 해도 `^`·`~`·`6.*`·`>=v12.22.7`·
  `18 || 20 || >=22`·`>=16 || 14 >=14.17` 처럼 다양하고, 특히 `1.2.3`(고정 버전)이 `operator: ''` 로
  나와 `*`(ANY)와 같은 문자열을 쓴다 — 직접 파서였다면 고정 버전 선언이 무제약으로 흘렀을 것이다
  (구현 중 실측). devDependency 하나가 옳은 값이다.

## 결과 (Consequences)

- **좋은 점**: 「자동 검사는 없다」는 ⚠ 경고와 20줄짜리 수동 스니펫, 그리고 그 스니펫이 스모크일 뿐임을
  설명하던 caveat 문단이 통째로 사라진다. 드리프트의 **원인**(휘발성 사실의 산문 보관)이 제거되므로
  경보를 관리할 필요도 없다. 실패 메시지가 붙여넣을 범위를 그대로 준다.
- **감수하는 비용 ①**: 어떤 패키지가 바닥을 정하는지 **한눈에 안 보인다**. 명령 한 줄이 필요하다.
- **감수하는 비용 ②**: 트리가 floor 를 **내리면** 과소선언으로 RED 가 되어 `engines` 를 넓히는 편집이
  강제된다. 여기에는 실질적 긴장이 있다 — 예컨대 트리가 Node 25(비-LTS) 배제를 그만두면 게이트는
  25.x 허용을 요구하는데, Fleet 은 그 버전을 테스트하지 않는다. 지금은 `.nvmrc`/CI 가 실제 테스트
  대상을 핀하고 있어 감수 가능하다고 보되, **의도적 협소화가 필요해지면 계약 자체를 고친다**(조용히
  어긋난 채 두지 않는다).
- **정직한 한계**: 모델의 정의역은 정식 릴리스 버전이다. semver 가 상한에 붙이는 합성 `-0` 은 벗기고,
  실질 prerelease 경계는 근사하지 않고 throw 한다. 또 `determinants` 는 leave-one-out 정의라 **서로 다른
  두 선언이 같은 경계를 강제하면 둘 다 안 잡힌다**(목록이 비어도 「제약이 없다」가 아니다) — 진단용
  값이며 합격 판정에는 들어가지 않는다.
- **재검토 트리거**: 의도적 협소화 요구가 실제로 발생 · npm 이 optional/dev 의 engines 검사 의미론을
  바꿈 · 워크스페이스(모노레포) 도입으로 루트가 여럿이 됨.
