01

요약 (Executive Summary)

Fleet 은 여러 LLM(구독제 CLI + API)이 하나의 작업방에서 협업해 사용자의 프로젝트를 완수하는 데스크톱 앱이다. 이 계획서는 그것을 브라우저에서 쓰는 멀티테넌트 SaaS 로 전환하는 인프라 설계를 담는다. 전환이 현실적인 근거는 하나다 — Fleet 의 오케스트레이션 코어(src/main/core/*)는 처음부터 Electron 비의존 순수 TypeScript 로, 6개 포트 인터페이스 (Store · LlmSession · ApiProvider · CommandRunner · SecretCrypto · ApprovalGate) 뒤에 격리되어 있다. 어댑터만 교체하면 오케스트레이션 두뇌는 서버로 거의 그대로 이식된다.

반대로 가장 큰 제약은 기술이 아니라 라이선스다. Anthropic(2026-04) · Google(2026-03)은 소비자 구독 OAuth 토큰의 공식 도구 외 사용을 금지했다. 따라서 "내 Claude Pro 구독을 클라우드에 연결" 은 지원 불가능한 경로이고, SaaS 는 API 키 전용(BYO 키 또는 플랫폼 미터드 키)으로 설계한다. CLI 바이너리 자체는 전부 API-키 환경변수 인증을 지원하므로, 오케스트레이션 UX 는 그대로 유지된다.

결정 영역 권고 한 줄 근거
샌드박스 격리 K8s + Kata Containers microVM (MVP 는 gVisor 허용, plain 컨테이너 불가) 에이전트는 LLM 이 생성한 임의 코드를 실행하고, Fleet 의 path-guard 는 명시적으로 advisory — 테넌트 경계는 커널 경계여야 한다.
워크스페이스 git-native 에페메럴 체크아웃 (내부 git 미러 → clone → 결과 브랜치 push) 워크스페이스 계층이 이미 git-aware. diff/감사/롤백이 공짜고, 크로스테넌트 영속 볼륨이 사라진다.
실시간 전송 SSE (서버→브라우저) + REST POST (명령/승인) 코어가 이미 SSE 계열 이벤트 스트림으로 정규화. Last-Event-ID 재개, 프록시/CDN 통과. WebSocket 이 더 주는 것이 없다.
LLM 인증 API 키 전용 — BYO 키(KMS 암호화) + 플랫폼 미터드 키(마진) 구독 OAuth 의 3rd-party 사용은 ToS 금지(§3). CLI 는 API-키 env 로 클라우드에서 그대로 구동.
데이터스토어 Postgres(tenant_id RLS) + 오브젝트 스토리지 + Redis 급 캐시/큐 Store 인터페이스가 교체 전제로 설계됨. RLS 는 애플리케이션 버그 아래의 2차 테넌시 안전망.
02

현재 아키텍처 (As-Is)

현재 Fleet 은 단일 Electron 프로세스 트리다. 별도 데몬·HTTP 서버는 없고 main 프로세스가 곧 백엔드다. 플래너가 목표를 작업 그래프로 분해하고, 역할(planner / implementer / reviewer / summarizer)을 정책에 따라 LLM 에 배정하며, implementer CLI 가 로컬 워크스페이스 디렉터리를 직접 편집하고, verify 계층 (test/lint/typecheck)이 통과할 때까지 루프를 돈다.

로컬 워크스페이스

사용자가 고른 디렉터리 — CLI 가 직접 파일 편집, git 연동

SaaS 전환 관점에서 로컬 머신에 결박된 요소와 그 함의:

  • 구독 CLI 인증 — 바이너리가 머신에 설치되고 개별 로그인되어 있어야 한다. 클라우드에서는 라이선스 문제로 이 경로 자체가 막힌다(§3).
  • 파일시스템 워크스페이스 — OS 폴더 다이얼로그로 고른 로컬 디렉터리. 클라우드에서는 세션별 에페메럴 워크스페이스와 코드 입출력 경로(git)가 필요하다(§7).
  • OS 키체인 시크릿 — Electron safeStorage(DPAPI/Keychain). 클라우드 등가물은 KMS 봉투 암호화다(§12).
  • 단일 JSON 파일 store — 동기 스냅숏 쓰기. 멀티유저 동시성에서 생존 불가 → Postgres 로 교체(§8). 교체는 설계 시점부터 예정되어 있었다.
  • 신뢰 모델 — ApprovalGate 는 "모달 앞의 신뢰된 한 사람" 을 가정한다. 테넌트 경계·authz 가 어디에도 없다. 위협 모델 자체를 뒤집어야 한다(§10).
이식의 지렛대. 코어 엔진이 순수 TS 이고 모든 외부 접점이 포트 인터페이스라는 사실이 이 계획 전체의 비용을 결정한다. "재작성" 이 아니라 "어댑터 교체 + 재배선" 이다. §5 의 매핑 표가 그 작업 목록이다.
03

비즈니스 제약 — LLM 구독 라이선스 (ToS)

이 문서에서 가장 중요한 비기술 섹션. 데스크톱 Fleet 의 차별점인 "구독제 CLI 를 그대로 에이전트로" 는 클라우드에서 재현할 수 없다. 2026년 상반기 기준 각 벤더의 소비자 구독 OAuth 정책:

공급자 구독 OAuth → 3rd-party/클라우드 API 키 (headless CLI 포함) 비고
Anthropic (Claude) 금지 (2026-04) 허용 구독 토큰은 공식 도구 외 사용 금지. ANTHROPIC_API_KEY 로 Claude Code CLI 구동 가능.
Google (Gemini) 금지 (2026-03) 허용 동일 구조. Gemini CLI 는 API-키 인증 지원.
OpenAI (Codex) 회색 지대 허용 명시 금지·허용 모두 없음 → 금지로 간주하고 설계 (보수적 원칙).

결론으로 지원 가능한 두 경로:

  • 경로 A — BYO API 키: 사용자가 자신의 provider API 키를 등록(테넌트별 KMS 암호화). LLM 비용은 사용자가 provider 에 직접 지불, 플랫폼은 좌석/컴퓨트 요금을 받는다.
  • 경로 B — 플랫폼 미터드 키: 플랫폼 소유 키로 대행 호출하고 토큰 사용량에 15–30% 마진을 붙여 재판매. 키 관리 부담이 없어 온보딩이 가장 매끄럽다.
포지셔닝 분리. 데스크톱 Fleet = 구독 CLI 의 집 (개인, 자기 머신, 자기 구독). SaaS Fleet = API-키/팀 제품 (협업, 격리 실행, 과금). 상호 잠식이 아니라 세그먼트 분리다. 장기 escape hatch 로 "로컬 러너 하이브리드" (사용자 머신을 러너로 등록, 구독 CLI 는 사용자 머신에서 실행)를 Phase 3 에 남겨두되, 이 역시 별도 ToS 검토가 필요하다.

06

세션 샌드박스 설계

샌드박스는 이 시스템에서 유일하게 "적대적일 수 있는 코드" 가 실행되는 곳이다. 에이전트는 LLM 이 생성한 임의 명령을 실행하고(verify 루프의 npm install·테스트 실행 포함), Fleet 자체의 path-guard 는 문서화된 대로 advisory 다. 격리 티어 선택:

티어 경계 부팅 지연 밀도 호환성 판정
runc 컨테이너 네임스페이스 (커널 공유) ~수십 ms 최고 완전 기각 — 커널 취약점 하나가 곧 테넌트 경계 붕괴
gVisor 유저스페이스 커널 (syscall 필터) ~100ms 높음 빌드 툴체인 일부 갭 MVP 허용 — Phase 0–1 과도기 티어
Kata / Firecracker microVM 하드웨어 가상화 ~125ms–1s 중간 거의 완전 권고 — GA 기준 티어, 커널 경계 = 테넌트 경계

샌드박스 내부 — 세션당 1 microVM

러너 심 (runner shim)

유일한 제어 채널. 오케스트레이터와 gRPC 스트림 — spawn / stdin / stream-json·JSONL stdout 릴레이 / kill-tree / 파일 ops. CommandRunner·cli-session 의 클라우드 어댑터.

CLI 에이전트 + 툴체인

claude · codex · gemini (API-키 env 인증, 세션 resume 상태 디렉터리) + node/git/테스트 러너 등 verify 툴체인 이미지.

에페메럴 워크스페이스

git clone 으로 채워지는 일회용 암호화 디스크. 세션 종료 시 파기 — 결과는 push 된 브랜치만 남는다.

네트워크: 이그레스 프록시 외 전면 차단 (NetworkPolicy default-deny) · 시크릿: 스폰 시 단명 주입, 이미지에 미포함

운영 최적화 두 가지:

  • 웜풀 — CLI·툴체인이 설치된 microVM 을 미리 부팅해 풀로 유지. 세션 시작 = 풀에서 꺼내 clone + 키 주입. 체감 시작 지연을 초 단위로 낮춘다.
  • 유휴 하이버네이션 — N분 무활동 시 워크스페이스를 git 스냅숏(+CLI 세션 상태 디렉터리를 오브젝트 스토리지에 스냅숏)하고 VM 을 kill. 재개 시 re-clone + CLI 세션 resume(코어가 이미 지원). 샌드박스-초 비용의 최대 절감 레버(§15).
07

워크스페이스 — git-native 전략

"로컬 폴더" 의 클라우드 등가물로 영속 네트워크 볼륨 대신 git-native 에페메럴 체크아웃 을 채택한다. 프로젝트마다 내부 bare 미러를 두고(외부 GitHub/GitLab 연동 시 동기화), 샌드박스는 시작할 때 clone 하고 끝날 때 결과 브랜치를 push 한다.

워크스페이스 수명주기

1 · 연결

사용자 repo → 내부 git 미러 동기화 (또는 빈 프로젝트 초기화)
→

2 · 시작

웜풀 VM 할당 → shallow clone → 세션 브랜치 생성
→

3 · 작업

implementer CLI 편집 · verify 루프 · 중간 커밋 (diff = 감사 단위)
→

4 · 완료

결과 브랜치 push → 리뷰/PR → 사용자 repo 반영
→

5 · 파기

VM · 디스크 폐기. 영속물 = push 된 브랜치뿐

볼륨 방식 대비 트레이드오프:

  • 얻는 것 — diff 기반 감사·롤백 무료, 크로스테넌트 영속 볼륨 제거(공격면·비용), 네트워크 FS 지연 제거, 하이버네이션이 자연스러움(스냅숏 = push).
  • 비용 — 대형 repo 의 clone 지연(shallow/partial clone 으로 완화), git 미러 서비스 운영, 비-git 자산(대용량 바이너리)은 오브젝트 스토리지 별도 경로 필요.
08

데이터 계층

기존 StoreState(projects · tasks · rooms · messages · events · sessions)를 Postgres 스키마 영역으로 전개한다. 모든 테이블에 tenant_id 를 강제하고 Row-Level Security 를 켠다 — 애플리케이션 계층의 테넌시 버그가 나도 DB 가 교차 조회를 거부하는 2차 안전망.

스키마 영역 주요 테이블 특성 · 보존
테넌시 orgs · users · memberships · api_tokens 영구 보존 · RLS 루트
프로젝트 projects · repos(미러 참조) · role_assignments 영구 · 프로젝트당 미러 1
런/세션 runs · tasks · llm_sessions · sandboxes 런 = 작업그래프 스냅숏 · 상태머신 컬럼
대화 rooms · messages 대용량 본문은 오브젝트 스토리지 오프로드 옵션
이벤트/감사 events (append-only) 월 파티셔닝 · 핫 90일 → 콜드 아카이브(오브젝트 스토리지)
승인 approvals · approval_policies 상태머신(§11) · 전 결정 감사 연동
과금 usage_events · invoices 미터링 파이프라인 소스 · 불변
  • 오브젝트 스토리지 — 아티팩트(빌드 산출물·로그 원문·하이버네이션 스냅숏)는 테넌트 프리픽스 아래, 스코프드 자격증명으로 접근.
  • 큐/캐시 — 런 큐·SSE 팬아웃 버퍼·웜풀 상태는 Redis 급 인메모리 스토어. 진실 원천은 항상 Postgres.
  • 이벤트 로그의 이중 역할 — 데스크톱과 동일하게 감사 추적이자 채팅방/작업보드 타임라인의 소스. append-only 를 스키마로 강제.
09

실시간 스트리밍 (SSE)

서버→브라우저 전송은 SSE 를 채택한다. 근거: 코어가 이미 모든 provider 출력을 SSE 계열 이벤트 스트림으로 정규화하고(providers/sse.ts), 데스크톱의 push 채널 (fleet:orchestrator:event · fleet:chat:stream 의 start|delta|end|error)이 SSE 이벤트 타입으로 1:1 번역된다. Last-Event-ID 로 재접속 resume 이 공짜고, 프록시/CDN 통과성이 WebSocket 보다 좋다. 양방향이 필요 없다 — 명령·승인은 REST POST 로 충분하다.

샌드박스

CLI stdout (stream-json/JSONL)
→

러너 심

gRPC 스트림 릴레이
→

오케스트레이터

기존 파서로 이벤트화 · 이벤트 로그 기록
→

게이트웨이

SSE 팬아웃 (룸 구독자별)
→

브라우저

EventSource · Last-Event-ID resume
  • 이벤트 타입 체계 — run.*(그래프/작업 상태) · chat.*(start|delta|end|error) · approval.*(요청/결정) · verify.*(결과) — 데스크톱 IPC 채널 체계를 계승.
  • 재접속 — 이벤트 로그가 진실 원천이므로, 끊긴 클라이언트는 Last-Event-ID 이후를 로그에서 재생받는다.
10

멀티테넌시 · 보안

위협 모델 전환. 데스크톱: "신뢰된 단일 사용자 + advisory 가드". SaaS: "에이전트 출력은 적대적일 수 있고, 테넌트도 적대적일 수 있다". 모든 계층 설계가 이 가정에서 출발한다.

5계층 격리 모델 (바깥 → 안)

L1 · 테넌트 신원

OIDC + 모든 요청에 tenant_id · Postgres RLS 가 애플리케이션 버그의 백스톱

L2 · 컴퓨트

세션당 microVM 1 (하드웨어 가상화 경계) · 내부에도 seccomp + no-new-privileges

L3 · 네트워크

NetworkPolicy default-deny · 샌드박스 → 이그레스 프록시만 · allowlist(LLM API·git 미러·opt-in 레지스트리) · 테넌트별 이그레스 로깅

L4 · 데이터

테넌트별 KMS DEK · 오브젝트 스토리지 테넌트 프리픽스 + 스코프드 자격증명 · 샌드박스 디스크 암호화 후 파기

L5 · 행위 통제

비동기 승인 게이트(§11) + append-only 감사 로그 — path-guard 는 심층 방어로 존속

11

승인 게이트 재설계 — 모달 → 비동기 큐

데스크톱 ApprovalGate 는 "사용자가 모달 앞에 있다" 를 가정한다. 웹에서는 사용자가 자리에 없다. 승인을 영속 큐 항목 으로 바꾸고, 기존 destructive-pattern blocklist 를 심각도 등급의 시드로 재사용한다: safe 자동 승인(정책 프리셋) · risky 사람 승인 필요 · destructive 기본 차단.

승인 상태 머신

requested → pending → approved / denied / expired (TTL → 기본 거부)

pending 진입 시: SSE 인앱 알림 + 이메일/모바일 푸시 · 모든 전이는 감사 이벤트 · auto-approve 는 정책 프리셋이 requested→approved 를 즉시 단락

  • 정책 프리셋 — 조직 단위로 "safe 클래스 자동 승인 범위" 를 설정. 예: 워크스페이스 내 파일 쓰기 auto, 패키지 설치 auto/ask, shell 임의 명령 ask, destructive 는 항상 차단.
  • 타임아웃 = 기본 거부 — fail-closed. 승인 대기로 런이 장시간 멈추는 문제는 "안전 경로 우선 계속(speculative continue)" 설계로 완화 — 승인 불필요한 다른 작업 그래프 노드를 먼저 진행한다.
  • 감사 — 요청·결정·정책 근거·행위자를 전부 이벤트 로그에 남긴다. 컴플라이언스(§13) 증적으로 직결.
12

시크릿 · KMS / 과금 · 미터링

시크릿. SecretCrypto 의 클라우드 어댑터는 KMS 봉투 암호화다. 테넌트별 DEK(데이터 암호화 키)를 KMS 루트 키로 감싸고, BYO API 키는 DEK 로 암호화해 Postgres 에 저장한다. 샌드박스에는 스폰 시점에 단명 자격증명으로만 주입(env 또는 tmpfs 파일)하고 이미지·스냅숏에는 절대 굽지 않는다. 하이버네이션 스냅숏 전에 시크릿을 반드시 스크럽한다.

미터링 → 과금. 사용량은 이벤트로 발행되고 파이프라인이 집계해 청구로 이어진다.

미터링 항목 단위 소스 과금 반영
샌드박스 컴퓨트 샌드박스-초 × 티어(vCPU/RAM) 세션 스케줄러 사용량 과금 본체
LLM 토큰 (플랫폼 키) input/output 토큰 × 모델 provider usage 응답 (코어가 이미 파싱) 원가 + 15–30% 마진
LLM 토큰 (BYO 키) 동일 동일 과금 없음 — 대시보드 가시화만
스토리지 GB-월 (미러 + 아티팩트 + 스냅숏) 스토리지 인벤토리 소액 종량
동시 세션 피크 동시성 스케줄러 쿼터 플랜 티어 결정 (좌석/플랜 요금)
13

관측성 · 운영

  • 상관 ID — tenant_id / run_id / task_id / session_id 를 모든 로그·메트릭·트레이스에 전파. 게이트웨이→오케스트레이터→러너 심→CLI stdout 까지 한 런을 끝까지 추적.
  • 스택 — OpenTelemetry 계열 수집 + 메트릭(Prometheus 호환) + 구조화 로그. 이벤트 로그(§8)는 감사용, 운영 로그와 분리.
  • 컴플라이언스 트랙 — append-only 감사 로그 + 승인 증적 + 접근 로그를 SOC 2 / K-ISMS 대비 형태로 설계 시점부터 축적 (인증 자체는 GA 이후 §16).
SLO (초안) 목표 측정
세션 시작 지연 (웜풀 히트) p95 < 5s 요청→첫 CLI ready 이벤트
토큰 스트림 지연 p95 < 500ms (심→브라우저) 스트림 타임스탬프 차
API 가용성 99.9% 게이트웨이 성공률
런 완주율 (인프라 귀책) > 99% 인프라 오류로 실패한 런 비율
승인 알림 전달 p95 < 30s pending→알림 발송

Phase 0 의 핵심 마일스톤은 화려한 것이 아니다 — "데스크톱과 동일한 오케스트레이션 런이 서버에서 완주한다" 하나다. 코어의 vitest 스위트가 서버 어댑터 조합으로 그대로 GREEN 이 되는 것이 이식 성공의 기계적 정의다.

비용 모델 스케치

세션당 원가의 지배 항은 샌드박스-초와 LLM 토큰이다. 범용 컴퓨트 단가 기준 추정:

드라이버 추정 단가 비고
microVM 2vCPU / 4GB ~$0.07–0.12 /시간 범용 K8s 노드 단가 환산 · 웜풀 오버헤드 별도 상각
병렬 실행 배수 × 동시 implementer 수 병렬 작업 실행(출하됨)이 켜진 런은 샌드박스 수가 곱해진다
LLM 토큰 (BYO) 원가 패스스루 플랫폼 수익 아님 — 좌석/컴퓨트 요금이 수익
LLM 토큰 (플랫폼 키) 원가 + 15–30% 마진 온보딩 최적 경로이자 마진 소스
스토리지 · 이그레스 소액 미러 + 아티팩트, GB-월

유닛 이코노믹스 예시 — implementer 3개가 병렬로 도는 1시간 오케스트레이션 런: 컴퓨트 ≈ 3 VM × 1h × $0.1 ≈ $0.3–0.5 + 토큰 비용(모델·규모 의존, 통상 컴퓨트를 수 배 상회). 가격 구조는 좌석(플랜) + 사용량(샌드박스-초·토큰) 2축이 자연스럽다. 최대 원가 절감 레버는 유휴 하이버네이션(§6) — 대화형 세션은 대기 시간이 지배적이라 벽시계 시간 대비 과금 가능한 샌드박스-초를 크게 줄인다.

미검증 가정. verify 루프(npm install·테스트)의 CPU/IO 부하가 밀도 경제성을 좌우하는데 실측 전이다. Phase 0 에서 대표 워크로드 프로파일링을 최우선 계측 항목으로 둔다(§16).

미해결 질문 (열림):

  • SOC 2 / K-ISMS 인증 착수 시점 — GA 전 트랙 축적, 인증은 수요(엔터프라이즈 파이프라인) 확인 후.
  • GPU / self-hosted 모델 지원 여부 — 클라우드 중립 스택이라 노드풀 추가로 열려는 있음.
  • 국가별 데이터 레지던시 — 멀티리전(Phase 3)과 함께 결정.
  • 병렬 실행의 가격 책정 — 배수 과금 그대로 vs 플랜별 동시성 캡.
