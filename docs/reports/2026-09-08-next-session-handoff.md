## 3. `audit.yml` 의 미검증 구간 — 반드시 인지할 것

머지 직후 `workflow_dispatch` 로 1회 돌렸다(run `34188440614`, **success**, 20초). 확인된 것은
**성공 경로뿐**이다 — 그때 `npm audit` 이 0건이라 두 레그가 다 0 으로 끝났다.

**아직 한 번도 실행되지 않은 코드**:

- `|| status=$?` 의 `-e` 조기종료 격리 — 실패 경로 전용
- `::warning::` 애노테이션 — `status != 0` 일 때만
- 레그 ②의 `if: ${{ !cancelled() }}` — 레그 ①이 성공하면 기본 `success()` 로도 돌기 때문에,
  이번 런은 이 조건이 **필요한 상황을 만들지 못했다**
- 실패 분기의 요약 렌더(닫는 코드펜스 · `npm audit fix` 안내)

즉 **실제로 권고가 뜨는 날이 이 잡의 첫 진짜 시험**이다. 그 전에 확인하고 싶으면 아래 프롬프트 2.

## 6. 이 세션의 실패에서 남기는 규율

**역사적 주장은 1차 증거로 확인하기 전에 쓰지 않는다.** 이 세션에서 두 번 연속 틀렸다:

1. **#319** — 「레포 선례대로 봇 PR 을 묶는다(#243 · nanoid)」. 실제 선례는 **정반대**였다 —
   #247·#277 둘 다 같은 날 봇 PR 을 개별 머지한 뒤 **봇이 놓친 잔여만** 사람 PR 로 냈다.
2. **#321** — 「부모 range 밖이라 봇이 PR 을 못 여는 자리를 덮는다」. #243 의 `js-yaml` 은
   패치가 4.3.0 이고 `electron-updater` 의 요구가 `^4.1.0` 이라 **range 안**이었고, 봇은 나중에
   #276 을 실제로 열었다. 같은 PR 의 「7주간 유사 4건」도 어떤 계수 규칙으로도 4가 안 나왔다
   (실제 3건 · 그중 2건은 dev 전용이라 설계 근거가 되지 못했다 → fail-hard 근거는 n=1).

둘 다 자가 적대 리뷰가 잡았지만, 리뷰가 없었으면 그대로 나갔을 것들이다. 과거 PR·이슈·락파일을
근거로 들 때는 **`mcp__github__*` 로 원문을 열고 락파일을 직접 읽은 뒤에** 쓸 것.

**뮤테이션 검증의 오라클을 먼저 검증한다.** #321 에서 뮤턴트 적용 여부를 `git diff` 로 판정했는데
신규 파일이라 항상 비어 있어, **미적용 뮤턴트가 「검출됨」으로 보였다.** `cmp` 로 바꿔 잡았다.
그리고 뮤턴트 집합이 `run:` 줄 텍스트만 건드려, **10/10 GREEN 을 유지한 채 잡을 무력화하는 우회
5종**(주석 잔류 · `|| true` · `if:` skip · 잡 레벨 `continue-on-error` · 얕은 주석 파서 절단)을
하나도 짚지 못했다. 뮤테이션은 **「무엇을 못 잡는가」를 먼저 물은 뒤** 설계할 것.

**Codex 한도 소진 시 경로**: `AGENTS.md:186` 풀 렌즈 자가 적대 리뷰 → PR 코멘트를
`[codex-gate-fallback] head=<40자 SHA>` 로 **시작**해야 머지 게이트를 통과한다. `## ` 같은
접두가 붙으면 첫머리 앵커 조건을 못 맞춰 차단된다(이 세션에서 한 번 걸렸다).
