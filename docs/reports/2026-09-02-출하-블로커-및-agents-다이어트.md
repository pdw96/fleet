### 1.3 실제 블로커 — 절차적 2건

#### [B-1] AGENTS.md 릴리스 절차 2항이 «다음 릴리스» 전체를 막는다 (해소 쉬움)

`AGENTS.md:295-299` 가 CHANGELOG 미착지(#304)를 이유로 이렇게 적는다:

> **CHANGELOG — ⚠ 아직 선행 전제다(#304 미착지).** … **지금 태그를 밀면 미서명 경고 우회 안내가
> 릴리스 노트에 실리지 않는다** … 첫 1.0 릴리스 전에 #304 의 CHANGELOG + `--notes-file` 전환을 먼저

**문면은 「첫 1.0 릴리스 전에」로 1.0 에만 조건을 걸고 있는데, 운영상으로는 0.1.x 를 포함한 모든
후속 릴리스를 정지시키고 있다.** 실제 위험(미서명 경고 안내 부재)은 실재하지만, 그 완화책은
`--notes-file` 전환만이 아니다 — **README 설치 절에 우회 절차를 넣고 릴리스 노트에서 링크**하면
0.1.x 수준에서는 충족된다(#304 ①②만 필요, ③ 불요).

#### [B-2] ADR-0018 의 리듬이 4~8주짜리 마일스톤 뒤에 걸려 있다 (핵심)

ADR-0018 은 「준비되면 낸다」를 **명시적으로 기각**했다:

> **리듬 없이 마일스톤 릴리스**: 「준비되면 낸다」가 지금 79건/0릴리스를 만든 상태 그 자체다.
> 기준이 주관적이라 무한히 미뤄진다. → 기각.

그런데 같은 ADR 이 정한 리듬의 **개시 조건**은 이것이다:

> **릴리스를 고정 리듬으로 만든다** — **W4 종료 시** `v1.0.0-rc.1`, 이후 **2주 주기**.

W1~W4 는 이슈 13건(#294~#306)이고 어드바이저 로드맵상 **4~8주 트랙**이다. 즉 **첫 출하가
마일스톤 완료에 걸려 있어, 리듬이 시작되기 전까지는 여전히 「준비되면 낸다」다.** ADR 이 기각한
구조가 그 ADR 의 개시 조건에 그대로 남아 있다.

여기에 자기감시 공백이 겹친다. ADR-0018 의 재검토 트리거 ①은 *"2주 주기가 두 번 연속 지켜지지
않으면"* 인데, **리듬이 아직 시작되지 않았으므로 이 트리거는 영원히 발동하지 않는다.** 리듬 개시
지연을 감지하는 장치가 없다.

#### [B-3] 잔여 리스크 — stable 태그에는 해당 없음 (참고)

stable 태그(`v0.1.1`)는 `latest.yml` 갱신이라는 정상 경로이므로 이 항목에 막히지 않는다.
→ **RC 를 먼저 내려는 현 로드맵이 오히려 미검증 경로를 먼저 밟는다.**

npm 프로젝트 픽스처(`NPM_WS_PKG`)로 바꿔 **원래 의도(verify 경로 검증)를 보존**했다.

⚠ **중요한 반론과 그 처리.** `AGENTS.md` 의 장황함 상당수는 **Codex 리뷰에서 반복 지적된 것을
문면화한 결과**다(본문이 여러 번 그렇게 말한다 — 예: `:70` *"이 구분을 문면에 두지 않아 리뷰에서
반복 지적된 항목 — ADR-0013"*). 그냥 지우면 같은 지적이 재발한다. 따라서 **아래 후보는 전부
「삭제」가 아니라 「이동 + 포인터 잔류」**다. 근거·역사는 ADR 에, 실행 절차는 스킬에, 현재 값은
게이트 출력에 두고, `AGENTS.md` 에는 **어디를 보라는 한 줄**만 남긴다.

### 2.2 후보 5건

*"게이트 실패 메시지가 붙여넣을 범위를 그대로 준다"*(`:151`)고 적는다. 즉 **실패했을 때만 필요한
정보를, 실패 메시지가 이미 주는데, 매 세션 로드되는 문서에 상주**시키고 있다.

**제안**: 절차·명령은 제거하고 ADR-0016 포인터 + *"실패 시 게이트 메시지가 정확한 범위를 준다"*
1줄. **남길 것**: *"왜 optional 만 제외하고 dev 는 포함하는가"*(Arborist 가 ideal tree 에서 engines 를
먼저 검사한다는 실측) — 이건 게이트 메시지가 설명하지 않는 설계 근거다.

#### [D-3] Codex required check 화 보류 근거 — `AGENTS.md:174-185` (12줄) → 약 10줄 절감

**현 상태**: `openai/codex-action@v1` 이 API 키 기반이라는 점, `CODEX_ACCESS_TOKEN`+`codex exec` 가
Business/Enterprise 전용이라는 점, trusted private runner 제약, 액션 issue #92 등 **보류 결정의
근거**를 12줄로 서술한다.

**이미 있는 곳**: **ADR-0001**(「Codex 를 required CI 머지 게이트로 만들지 않는다」)이 바로 그
결정의 기록이다. ADR 의 존재 이유가 「기각한 대안과 근거를 남기는 것」이므로 이건 정의상 중복이다.

**제안**: *"required check 화는 보류다 — 근거·기각 대안·재검토 트리거는 ADR-0001."* 1~2줄.

#### [D-4] 백로그 gh 명령 상세 — `AGENTS.md:270-283` (14줄) → 약 10줄 절감

**현 상태**: `gh issue edit --parent` / `--add-blocked-by` / `--add-blocking`,
`gh api repos/…/dependencies/…`, `gh project item-list` 기본 limit 30, `gh ≥2.94`·`≥2.95` 버전 요구가
산문에 있다.

**문제**: ① **gh CLI 매뉴얼이라 버전이 오르면 낡는다**(이미 「구식 `gh api … /sub_issues`+DB id 불요」
같은 정정 흔적이 본문에 있다) ② `.claude/skills/fleet-backlog-induction/SKILL.md` 에 같은 절차가
실행 래퍼로 또 있다.

본문은 *"산문은 이 절이 권위, 스킬은 실행 래퍼"*(`:225`)라고 선언하는데, **실행 명령까지 산문이
권위를 주장하면 2중 유지가 된다.** 권위 경계를 바꾸는 게 맞다.

**제안**: **「무엇을·왜」는 `AGENTS.md`, 「명령·플래그·버전」은 스킬이 권위**로 뒤집는다.
`AGENTS.md` 에는 라벨 분류축(`area:*`/`tier:*`/`type:*`) · sub-issue 편입 · 의존성은 산문 주석이
아니라 플랫폼 관계로 인코딩한다는 **원칙**만 남긴다.
⚠ 이 권위 뒤집기는 산문 한 줄 수정이 아니라 규약 변경이므로 **ADR 감**이다.

#### [D-5] Codex 봇 관측 절차 — `AGENTS.md:246-263` (18줄) → 약 12줄 절감

**현 상태**: 자동리뷰 지연 시간(7~20분), 👍 리액션이 게이트가 아닌 이유, commit_id 결속 판정,
`reviews`/인라인/이슈 코멘트/리액션 4채널 폴링 방법, 봇 로그인 필터, 레이트리밋을 서술한다.

**이미 집행하는 것**: `.claude/hooks/require-codex-review.mjs`(PreToolUse, **fail-closed**,
canonical allowlist)가 현재 head 에 결속된 Codex 신호 부재 시 머지를 **기계 차단**하고, 본문이
스스로 *"차단 메시지가 복사 가능한 정확한 재시도 명령을 준다"*(`:262`)고 적는다. 즉 **사람이
4채널을 폴링해 판정할 필요가 이미 없다.**

**제안**: *"머지 인가는 hook 이 강제한다(fail-closed). 차단 시 메시지가 정확한 재시도 명령을 준다.
대기는 `/loop` 로."* 로 축소.
**남길 것**: 👍 가 인가 신호가 아닌 이유 1줄(44R P1 — 리액션은 commit 결속이 없다). 이건 사람이
**hook 을 우회하려는 유혹**을 받는 지점이라 근거가 눈에 보여야 한다.

**진행 상태**: D-3·D-5 착지 완료(2026-09-02) — `verify` GREEN, 상호참조(`:187` 「아래 44R 절」) 유지

**net-zero 검토**: 이 다이어트는 절차·게이트·문서를 **빼기만** 하므로 어드바이저 원칙 6의 짝짓기

`fleet-backlog-induction` 은 매 세션이 아니라 **호출 시에만** 로드되므로 상시 컨텍스트 비용은 여전히
줄어든다는 점이 이동의 근거다.
