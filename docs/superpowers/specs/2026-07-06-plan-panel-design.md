# 판사 패널 계획 수립 파이프라인 — fleet-planner · fleet-plan-judge · fleet-plan-panel 설계

- 날짜: 2026-07-06
- 상태: 설계 승인 대기
- 산출물: `.claude/agents/fleet-planner.md` · `.claude/agents/fleet-plan-judge.md` · `.claude/skills/fleet-plan-panel/SKILL.md` · `fleet-backlog-induction/SKILL.md` 한 줄 참조 추가

## 1. 배경·목적

Fable 5가 2026-07-07 이후 API 요금제 전용으로 전환된다. 현재 파이프라인(계획=Fable, 검토=GPT 5.5,
실행=Opus)에서 계획 수립 품질을 Opus 4.8로도 보전해야 한다. 단일 패스 지능 격차는 **추론 시점
컴퓨트(독립 초안 N개 + 독립 채점)**로 보전한다 — Opus 4.8 다중 패스가 Fable 단일 패스를 계획
품질에서 앞서는 것을 노린다.

설계 근거로 Codex 리뷰 502건 전수조사(2026-07-06, 이슈 코멘트 126 + PR 인라인 376)를 수행했다.
결과는 메모리 `codex-review-pattern-taxonomy`에 보존. 핵심:

- **Codex 강점**: 외부 API 계약 drift(~91건) · 보안 가드 우회/비밀 유출(P1의 57%) ·
  동시성 race(~57건) · 엣지 경계값(~83건) · fail-open(~43건) · (체크포인트 한정) 타입 ripple
  전수 추적, "테스트로 정책 고정" 요구.
- **Codex 구조적 공백**: 아키텍처 근본 대안·프레임 전복(0건) · 성능 정량 · 테스트 커버리지
  요구/가짜 green(4/376) · 타입 설계 품질 · 런타임 실측 · 솔로 pre-1.0 ROI 판단.
- **운영 특성**: 체크포인트 리뷰(7~16KB 정밀)와 자동 PR 리뷰(clean 한 줄)의 깊이 편차 극단,
  재검증 라운드는 얕음(첫 리뷰가 실질 방어선).

## 3. 컴포넌트

### 3.1 `.claude/agents/fleet-planner.md` — 계획 초안 전담

- **도구**: Read, Glob, Grep, WebSearch, WebFetch, context7 2종. **읽기 전용** — Write/Edit/Bash
  미보유(도구 수준 강제, fleet-refuter 선례 = Codex PR#192 P2).
- **model**: `inherit`.
- **본문 규율**:
  1. `brain.md` 선행 독해(전체 src/ 탐색 대체).
  2. 디스패치 프롬프트가 지정한 **각도 하나로만** 계획: `리스크 우선`(위협·회귀·롤백 중심 순서) /
     `MVP 우선`(최소 슬라이스·조기 가치) / `계약 우선`(인터페이스·타입·프로토콜 먼저 고정).
  3. 기존 `docs/superpowers/plans/` 양식 준수(태스크 분해·TDD RED→GREEN·검증 명령).
  4. **Codex 선반영 체크리스트**(전수조사 산물 — 초안 자체에 반영해 체크포인트 라운드 절약):
     타입·계약 변경 시 ripple 전파 지점 전수 나열 / 에러·분류불가 경로 fail-closed 방향 명시 /
     합의사항마다 고정(pin) 테스트 지정 / 경계값 케이스 열거 / 수정 대상의 형제 경로 스윕 목록.
  5. 근거 없는 파일 경로·라인 인용 금지 — 인용은 실측(Read/Grep)한 것만.
  6. **draft≠judge** — 자기 초안을 스스로 확정·비교하지 않는다. 출력은 채점 후보다.
- **출력**: 계획 초안 전문(최종 텍스트가 그대로 수확된다 — 한국어).

### 3.2 `.claude/agents/fleet-plan-judge.md` — 채점 전담

- **도구**: Read, Glob, Grep, context7 2종(계약 렌즈 채점에 현행 문서 대조). 읽기 전용.
- **model**: `inherit`.
- **루브릭 8렌즈, 두 그룹** — 디스패치 시 맡을 그룹을 지정:
  - **공백 그룹**(Codex가 구조적으로 안 잡는 축): ① 아키텍처 대안 도전 — 이 프레임 자체가
    최선인가, 더 싼 구조는 없는가 ② 솔로 pre-1.0 ROI/범위 — ADR-0003 렌즈 ③ 검증가능성 —
    라이브 스모크 계획 포함 여부·가짜 green 방지·verify 전략 ④ 태스크 입도·의존 순서.
  - **Codex 강점 그룹**(이중 방어): ⑤ 계약 ripple 완전성 ⑥ 보안 fail-closed ⑦ 엣지·경계값
    ⑧ 테스트 고정(합의→테스트 매핑).
- **본문 규율**: draft를 작성한 인스턴스와 반드시 분리(draft≠judge) / 점수만 내지 말고 근거를
  계획 내 위치로 인용 / 초안 간 차이가 없으면 "각도 붕괴"를 보고.
- **출력**: 초안별 렌즈 점수(1~5)+근거 · 승자 지목 · **패자에서 이식할 아이디어** 목록(합성 재료).

### 3.3 `.claude/skills/fleet-plan-panel/SKILL.md` — 절차 문서 (L2-only)

`fleet-backlog-induction`과 동형의 간결 한국어 절차 문서. frontmatter description에 트리거
문구("판사 패널 계획", "패널로 계획 수립") 명시. `fleet-backlog-induction` 3단계의 plan 작성을
이 스킬로 위임하도록 induction 문서에 한 줄 참조 추가.

## 4. 절차 흐름

```
0. 입력 확인 — 승인된 스펙(docs/superpowers/specs/) 필수. 없으면 중단하고 브레인스토밍부터.
1. 규모 판정 — 소형(≤2파일·신규 계약 0·단일 PR)이면 패널 생략, 메인 루프 직접 계획. 고지 필수.
2. find: fleet-planner ×3 병렬 디스패치(리스크/MVP/계약 각도). 스펙 전문 + 대상 이슈 컨텍스트를
   프롬프트에 싣는다(워킹트리 밖 컨텍스트는 호출자가 적재, 공개 GitHub 리소스는 WebFetch로
   조회 — refuter와 동일 규약).
3. judge: fleet-plan-judge ×2 병렬(judge A=공백 그룹, judge B=Codex 강점 그룹). 초안 3개 전문 전달.
4. 합성(메인 루프): 승자 골격 + 이식 아이디어 + 판사 지적 반영 →
   docs/superpowers/plans/YYYY-MM-DD-<slug>.md 작성. 판정 근거(판사 점수 요약)를 문서 머리말에 기록.
   사용자 확인.
5. (선택) GPT 5.5 외부 검토 — 사용자가 원하면 전달용 요약 출력 후 대기, 피드백 반영.
6. (조건부) Codex 체크포인트 — 대상 이슈가 있으면 계획을 이슈 코멘트로 게재 + `@codex review`
   순수 한 줄(산문 금지 — 파서가 놓침). 이슈가 없으면 생성/생략을 사용자에게 질문.
   리뷰 반영 → 통과까지 반복.
7. 실행 인계 — superpowers:executing-plans / subagent-driven-development.
```

## 5. 에러 처리·강등 규칙

| 상황 | 처리 |
|---|---|
| planner 일부 실패 | 초안 ≥2면 진행. 1개면 "단일 초안 + judge 채점"으로 강등 + 사용자 고지(조용한 강등 금지) |
| judge 전멸 | 메인 루프가 8렌즈 직접 채점, 자기채점임을 명시 |
| 판사 간 승자 불일치 | 렌즈별 점수 공개, 메인 루프 판정 + 근거를 계획 머리말에 기록 |
| 레이트리밋(Max 공유 소진) | planner 순차 재디스패치. 완료분 결과 재사용 — 전체 재시작 금지 |
| 각도 붕괴(세 초안 사실상 동일) | judge 생략, 사실 고지 후 단일 초안 취급 — 동일 초안 채점 토큰 낭비 방지 |

## 6. 검증 계획

1. **정적**: `npm run verify`의 skills lint 통과. 에이전트 frontmatter 형식이 기존 2종
   (fleet-finder/refuter)과 일치.
2. **드라이런 1회**: 다음 백로그 아이템에 실제 적용해 완주 — 각도 분화 여부·judge 판별력 관찰.
3. **성공 기준(측정 가능)**:
   - judge 지적 중 Codex 체크포인트가 중복 지적하지 않은 것 ≥1건(공백 렌즈 실효).
   - Codex 체크포인트 리뷰 P1 0건 통과(선반영 체크리스트 효과).
   - 미달 시 렌즈·체크리스트 조정(스킬 문서 수정으로 반영).
